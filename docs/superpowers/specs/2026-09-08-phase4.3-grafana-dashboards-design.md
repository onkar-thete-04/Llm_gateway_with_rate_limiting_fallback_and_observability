# Phase 4.3 — Grafana Dashboards Design

Date: 2026-09-08
Status: Approved

## Goal

Provide observability dashboards for the LLM gateway, backed by Prometheus
scraping the `/metrics` endpoint (Phase 4.2), plus the two runtime gauges the
dashboards need that do not yet exist.

Deliverables:

1. Full observability stack in `docker-compose.yml`: Prometheus + Grafana with
   provisioning.
2. Three Grafana dashboards: Operations, Business, Performance.
3. Two new metrics: provider status gauge, budget limit gauge.

## Scope decisions (user-approved)

- **Cache hit rates** are NOT included. No caching layer exists; panel is
  deferred until caching is built.
- **Provider health** is exposed via a new gauge emitted by `HealthMonitor`
  (not derived in PromQL).
- **Budget utilization** uses a new exported budget-limit gauge (not a manual
  dashboard variable).
- **Full stack** delivered: compose + prometheus + grafana provisioning.

## Architecture

```
gateway:8000/metrics  ──scrape 15s──►  prometheus:9090  ──query──►  grafana:3000
                                          │
                                          └─ retention 15d, storage volume
```

### docker-compose additions

- `prometheus`: image `prom/prometheus`, mounts `infra/prometheus/prometheus.yml`,
  scrape interval 15s, retention 15d, volume `prometheus_data`.
- `grafana`: image `grafana/grafana`, mounts datasource + dashboard provisioning
  and the three dashboard JSONs, env `GF_AUTH_ANONYMOUS_ENABLED=true`
  (`GF_AUTH_ANONYMOUS_ORG_ROLE=Viewer`), port 3000, volume `grafana_data`.
- Both depend on `gateway`.

### File layout

```
infra/
  prometheus/prometheus.yml
  grafana/provisioning/datasources/prometheus.yml
  grafana/provisioning/dashboards/default.yml
  grafana/dashboards/operations.json
  grafana/dashboards/business.json
  grafana/dashboards/performance.json
```

## New metrics (runtime code)

### 1. Provider status gauge

`app/observability.py`:

- `PROVIDER_STATUS = Gauge("llm_gateway_provider_status", "Provider health
  status", ["provider"])` — 0 healthy, 1 degraded, 2 down.
- `set_provider_status(provider, status)` helper with the same
  `_HEALTH_STATE_VALUES` mapping used by circuit state.

`app/resilience/health.py`:

- In `HealthMonitor.record()` after `_derive` updates `self._statuses`, compute
  the provider rollup: worst status across that provider's models, then
  `observability.set_provider_status(provider, worst)`.
- `HealthStatus` ordering: healthy < degraded < down (DOWN wins).

### 2. Budget limit gauge

`app/observability.py`:

- `BUDGET_LIMIT = Gauge("llm_gateway_budget_limit_usd", "Team budget limit in
  USD", ["team"])`.
- `set_budget_limit(team, limit_usd)` helper (0.0 when no budget configured).

Wiring:

- `app/main.py` lifespan: after loading effective team config, set
  `BUDGET_LIMIT` for each team from `team.budget.amount_usd` (None -> 0.0).
- `app/admin/overrides.py` `set_budget`: refresh the gauge after the override is
  written (effective value = override if present else configured amount).

## Dashboards

Every dashboard has template variables `$team`, `$provider` (multi-select, all)
and uses `$__rate_interval`.

### Operations (`operations.json`)

| Panel | Query |
|---|---|
| Provider status (table, color-coded) | `llm_gateway_provider_status{provider=~"$provider"}` |
| Circuit breaker state | `llm_gateway_circuit_breaker_state{provider=~"$provider"}` |
| Circuit transitions | `sum(rate(llm_gateway_circuit_breaker_transitions_total[$__rate_interval])) by (provider)` |
| Error rate | `sum(rate(llm_gateway_request_errors_total[$__rate_interval])) by (provider, error_type)` |
| Fallback events | `sum(rate(llm_gateway_fallbacks_total[$__rate_interval])) by (team, provider)` |
| Request rate | `sum(rate(llm_gateway_requests_total[$__rate_interval])) by (status)` |

### Business (`business.json`)

| Panel | Query |
|---|---|
| Per-team spend (timeseries) | `sum(increase(llm_gateway_cost_usd_total[$__rate_interval])) by (team)` |
| Per-team spend (bar) | `sum(increase(llm_gateway_cost_usd_total[24h])) by (team)` |
| Budget utilization % | `increase(llm_gateway_cost_usd_total[1d]) / llm_gateway_budget_limit_usd{team=~"$team"}` |
| Usage trend — requests | `sum(rate(llm_gateway_requests_total[$__rate_interval])) by (team)` |
| Usage trend — tokens | `sum(rate(llm_gateway_tokens_total[$__rate_interval])) by (team, type)` |

### Performance (`performance.json`)

| Panel | Query |
|---|---|
| Latency p50/p95/p99 | `histogram_quantile(<q>, sum(rate(llm_gateway_request_duration_seconds_bucket[$__rate_interval])) by (le, provider))` |
| Token throughput | `sum(rate(llm_gateway_tokens_total[$__rate_interval])) by (type)` |
| Requests/sec | `sum(rate(llm_gateway_requests_total[$__rate_interval])) by (provider)` |

## Testing

`tests/test_dashboards.py` (no docker required):

- Each `infra/grafana/dashboards/*.json` parses as JSON and has non-empty
  `uid`, `title`, and `panels`; datasource ref resolves to the provisioned
  Prometheus datasource.
- Every PromQL expression's referenced metric names are all defined in
  `app/observability.py` (regex-extract `llm_gateway_*` tokens, assert subset).
- `infra/prometheus/prometheus.yml` parses as YAML and has a scrape job whose
  target is the gateway service on port 8000.

Extend `tests/test_metrics.py`:

- `PROVIDER_STATUS` set when `HealthMonitor.record()` derives a status.
- `BUDGET_LIMIT` set from team config at startup; refreshed by admin
  `set_budget`.

## Non-goals

- Alerting rules / Alertmanager.
- Caching layer (cache hit rate panels deferred).
- Grafana users/teams/permissions beyond anonymous viewer.
